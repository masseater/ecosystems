# @r_masseater/fu4

This workspace is the engine of a GitHub Actions linter. Rust (`native/core`) parses YAML and run scripts and encodes the trees into one buffer; TypeScript reads that buffer without copying it and runs the rules that configs load as plugins. Its settings go in `fu4` in vite.config.ts. Build the addon with `vp run native`; the tests depend on that task.

The engine layers ship no rules. The official rules are the presets in `src/app/presets`, published as `@r_masseater/fu4/presets`. Keep rule logic in the presets and keep only parsing, the rule API and running rules in the engine layers. Give Rust code tracing spans. When `OTEL_EXPORTER_OTLP_ENDPOINT` is set, the spans go under the caller's trace.

The presets are the official fu4 rules: `actionlint` for actionlint's checks (`features/check-workflows`) and `zizmor` for zizmor's audits (`features/audit-workflows`), selectable per concern. They use only the rule API, so they run as plain TypeScript with no native code.

The rules return the same results as actionlint, shellcheck and zizmor. The conformance tests compare them with fixtures and expected results taken from those tools: `src/app/presets/fixtures/actionlint/` (actionlint 1.7.12), `src/app/presets/shared/shell/fixtures/shellcheck/` (shellcheck 0.9.0 run as actionlint runs it), `src/app/presets/shared/shell/fixtures/shellcheck-upstream/` (scripts from ShellCheck's own unit tests, which stay under ShellCheck's GPL-3.0 and out of the published package) and `src/app/presets/features/audit-workflows/fixtures/` (zizmor 1.32.0 with `--offline --persona auditor`). `src/app/presets/entities/expression/lib/fixtures/actionlint/`, `src/app/presets/shared/glob/fixtures/actionlint/` and `src/app/presets/fixtures/actionlint/lint-calls.json` hold the expressions, globs and workflows that actionlint 1.7.12's own Go tests pass to it, with what it returned; the README there says how they were recorded. `src/app/presets/entities/expression-tree/lib/fixtures/zizmor/` holds the expressions and evaluations that zizmor 1.32.0's own expression-engine unit tests pass to it, with what it returned, recorded the same way. `src/app/presets/features/audit-workflows/lib/fixtures/zizmor-units/` does the same for the unit tests in zizmor's own crate. `src/app/presets/features/audit-workflows/fixtures/zizmor-tests/` holds zizmor 1.32.0's own integration tests as they are; the test reads each invocation and the findings in its snapshot, and runs it against the same inputs. Do not edit the fixtures or expected results by hand; list an actionlint fixture that does not match in `src/app/presets/fixtures/actionlint-known-failures.txt`, and a zizmor test in `src/app/presets/features/audit-workflows/fixtures/zizmor-tests-known-failures.txt`, with the reason. Audits that query GitHub are tested against a fake `fetch`, and must never reach GitHub from a test.

`src/app/presets/shared/data/` is generated by `vp run generate-data` from GitHub's docs and schemas and from the zizmor repository; do not edit it by hand.
